## 1. 系统概述

TC_ScanSystem 是横沙监测项目的 **Web 管理端 + 监测展示端**（ASP.NET MVC5 + WebAPI2 + SQL Server）。它本身**不做数据采集**，而是：

1. **配置侧**：维护监测对象的层级结构（图层 → 部位 → 测点）、采集类型、设备与通信参数、协议，并向采集端**下发指令**（写入命令队列 `MK_Scan_Command`）；
2. **展示侧**：查询采集端写入的监测数据（`MK_DataValue` / `MK_Alert` / 按月分表 `FD_DynamicValue2yyyyMM`），以列表 + ECharts 曲线 + 三维模型方式呈现；
3. **运行侧**：单一站点内按 Area 划分"监测大屏 / 结构监测 / 系统管理"三块业务，配 RBAC（用户-角色-菜单）权限。

与同目录下的 `BH_ScanSystem`（采集端：Client/Listen/Server 现场采集程序）**通过同一个 SQL Server 数据库协作**：BH 负责"设备 → 数据 → 告警"的写入，TC 负责"配置 → 指令下发 → 查询展示"。二者没有进程间调用，唯一契约是共享表结构（详见第 10 节）。

### 4.2 指令下行链路（配置 → 采集端）

```
DeviceController.Send(DeviceResponse)（Areas\Scan\Controllers\DeviceController.cs:142）
  → Excute(Command, device)（:176）
      → new MK_Scan_Command { Command, DeviceID, CommunicationDeviceID, DeviceIden,
```

**这是本系统对外唯一的"实时控制"能力，且是异步的**（无 SignalR/消息队列，靠数据库轮询）。

## 5. 数据模型与实体关系

### 5.1 监测对象主链（结构监测核心）

```
MK_Layer 图层/结构物（背景图、图上坐标、ScanTypeId）
   │ 1:N（LayerId）
MK_Position 部位/测区（在图层上的框选区域：MapX/MapY/宽高、背景图）
   │ 1:N（PositionId）
MK_Point 测点（点名称、图上坐标、单位 Unit/Unit2、映射名 MapDataName/MapDataName2、
              ├─3 级阈值 MaxNum/MaxNum2/MinNum/MinNum2、标高 Height、ScanTypeId、DeviceId、Para1~5）
   │ 1:N（PointId）
MK_DataValue 静态采集数据（ScanValue1~6、CreateDate、Status）
MK_Alert     超限告警（ScanValue 实测、AlertValue 阈值、Level 告警级别、Status 处理状态、CreateDate）
FD_DynamicValue2yyyyMM  动态特征值月表（运行时按月建表，含 MAXValue/YXValue/AverageValue 等）
```

聚合视图（免去多层 join）：

| 视图 | 含义 |
|---|---|
| `View_MK_Point` / `View_MK_PointList` | 测点 + 部位 + 图层 + 设备 + 类型 + 单位（测点全息视图） |
| `View_MK_AutoScan` | 自动采集数据 + 测点/部位/图层/设备/类型全字段（数据查询主视图，`ID/ScanValue1~6/CreateDate`） |
| `View_MK_AlertList` | 告警 + 测点/部位/图层/设备/类型（告警中心主视图） |
| `View_MK_Layer` / `View_MK_Position` / `View_MK_Device` / `View_MK_ScanType` / `View_MK_CommunicationDevice` | 配置项带项目/类型名称的只读视图 |

### 5.2 采集设备域

```
MK_CommunicationDevice 通信设备/网关（CommunicationType、IP、Port、CommunicationCode、DataProtocol）
   │ 1:N（CommunicationDeviceId）
MK_Device 采集设备（DeviceProtocol 协议类型、DeviceIden 设备标识、Interval 采集间隔、
                    BeginTime 起始时间、DeviceTime 设备时钟、CRC 校验、Status 在线状态）
   │ 1:N（DeviceId）
MK_Point 测点
MK_Communication_Initialize / MK_Current_Communication  通信初始化参数与当前通信状态

MK_Scan_Command 命令队列（Command/Result/Status/DeviceIden/CommunicationIden/IsSystem）  ← 下行通道

```

## 10. 与 BH_ScanSystem（采集端）的协作关系

```
┌─────────────────────────── TC_ScanSystem（本文，Web 端）───────────────────────────┐
│ 配置：MK_Layer/MK_Position/MK_Point/MK_ScanType/MK_Protocol/MK_Device/MK_CommunicationDevice │
│ 指令：INSERT MK_Scan_Command(Status=0)                                              │
│ 展示：SELECT MK_DataValue / MK_Alert / FD_DynamicValue2yyyyMM / View_MK_*            │
└───────────────────────────────────┬─────────────────────────────────────────────────┘
                                    │  SQL Server（TC_Monitor / FD_ScanSystem）
┌───────────────────────────────────┴─────────────────────────────────────────────────┐
│ BH_ScanSystem（采集端）：Server（串口轮询 MCU32/Modbus）、Listen（TCP 50002 + FBG 导入）、Client（采集卡）│
│ 消费 MK_Scan_Command → 采集 → 换算 → INSERT MK_DataValue → 阈值比较 → INSERT MK_Alert │
│ 动态成果 → INSERT FD_DynamicValue2yyyyMM（按月自动建表）/ FD_DynamicValue3yyyyMM（FBG） │
│ 回写 MK_Scan_Command.Result/Status、MK_Device.Status                                 │
└─────────────────────────────────────────────────────────────────────────────────────┘
```

要点：
1. **接口即表结构**。TC 增删字段/改语义（如 `MK_Point.MapDataName` 作为通道映射名、`Para1~5` 作为换算系数、`IsCommand==3` 作为动态标记）会直接影响采集端解析。
2. **`MK_Scan_Command` 是双向契约**：TC 只写 `Status=0`，采集端负责置位与回填 `Result`；TC 的 `CommandQuery` 依赖该状态机。
3. **数据一致性不靠事务**：TC 查询用 `SET TRANSACTION ISOLATION LEVEL READ UNCOMMITTED`（`DataContextFactory.cs:31`）规避采集写入的锁竞争，代价是可能读到脏数据。
4. 动态数据**按月分表**，表名由代码拼接，历史范围查询需跨表 UNION（见 6.3、第 8 节）。
